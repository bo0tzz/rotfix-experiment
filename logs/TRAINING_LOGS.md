# Training logs

One JSON per run in `logs/`. Top level has `arch`, `params`, `res`; `hist` holds per-epoch records
followed by two summary records, `product_metrics` and `final_full_library`.

Per-epoch fields: `loss`, `sec`, and four accuracies —

- `oid_single` / `oid_tta` — held-out Open Images validation, single pass vs 4-rotation TTA
- `lib_single` / `lib_tta` — a **3,500-image subset** of the real library

For the C4-equivariant runs (`arch: p4_*`) single and TTA are **identical by construction**: rotating
the input cyclically permutes the logits, so 4-pass TTA is provably a no-op. Where the two columns
differ, the run is a non-equivariant architecture (`mnv4_*`) that genuinely needs the four passes.

> **Caveat.** The per-epoch `lib_*` numbers are the 3,500-image subset and are pace checks, not
> results. They misled us three times during the project. Authoritative numbers come from the full
> 13,352-image set — the `product_metrics` record, or recomputed from `results/*.npz` via
> `src/score.py`.
